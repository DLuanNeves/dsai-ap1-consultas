# Diário do Loop - Servidor MCP (08/10/2026)

## 1. Qual perna da tríade o servidor abre?
O servidor MCP que projetamos atua diretamente na perna da **Ação (ou Execução)**. Ele permite que o agente de IA deixe de apenas conversar (gerar texto) e passe a ter impacto real no mundo, modificando o banco de dados do MarcaConsulta (criando pacientes e agendando consultas).

## 2. Teste Simulado: O que o agente escolheu e onde errou
* **O Prompt do Usuário:** "Agente, marque uma consulta para o paciente João (ID 55) com o Dr. Silva (ID 2) amanhã às 14h."
* **A Escolha do Agente (Volta 1):** O agente tentou usar a tool `agendar_consulta` (Escrita) diretamente, sem verificar a agenda.
* **Onde ele errou:** O agente causou um conflito de horário no banco de dados, pois não verificou se o Dr. Silva já tinha consulta às 14h. 
* **A Correção (Volta 2):** O servidor MCP foi ajustado. Ao ler a documentação (`DEFINICAO_TOOLS.md`), o agente entendeu que a tool `agendar_consulta` tem uma regra estrita: *"Antes de agendar, você DEVE OBRIGATORIAMENTE usar a tool `listar_consultas_medico`"*.
* **Resultado Final:** O agente usou a Leitura (`listar_consultas_medico`), viu que o horário estava ocupado, e respondeu ao usuário pedindo para escolher outro horário, em vez de quebrar a aplicação.

## 3. Lições aprendidas
* Criar a ferramenta (tool) não é suficiente. A documentação embutida (docstrings) é o que treina o comportamento do agente para não cometer erros na aplicação.
* Um servidor MCP seguro deve restringir as ações de escrita, exigindo passos de leitura anteriores (Human-in-the-loop ou regras programadas).
